# 二、完善对象级缓存（Content Cache）模拟器
Simulate a variety of existing caching policies by replaying request traces, and use this framework as a basis to experiment with new ones.

模拟器会读取trace数据集，每一行是一条request请求记录，request请求记录应采用空格分隔的格式，包含3列数据，同时还需要为额外的功能字段预留空间。
- time：应该是一个长整型long long int变量，但实际上可以是任意类型（为将来可能的 TTL 功能而设，目前并未使用）
- id：应该是一个长整型long long int变量，用于唯一标识对象。
- size：应该是一个 uint32 类型的数据，表示对象所占用的字节数。
- extra features：其他特性是可选的 uint16 类型数据。目前将这些数据视为分类特征（例如，对象类型）。

在启动过程中，模拟器会对该trace数据进行一项完整性检查。
trace数据文件放置在traces/目录下

## 如何获取trace数据集
### Generate your own traces with a given distribution
One example is a Pareto (Zipf-like) popularity distribution and Bounded-Pareto object size distribution. The "basic_trace" tool takes the following parameters:
how many unique objects
how many requests to generate for most popular object (total request length will be a multiple of that)
Pareto shape
min object size
max object size
output name for trace
Here's an example that recreates the "test.tr" trace for the examples above. This uses the "basic_trace" generator with 1000 objects, about 10000 requests overall, Pareto shape 1.8 and object sizes between 1 and 10000 bytes.
### Rewrite existing open-source traces(目前已有，无需实现)
Example: download a public 1999 request trace (trace description), rewrite it into our format, 和 run the simulator.
